# 063 — ELSEWHERE / CATALOGUE 0 — Every Object Gets a Route

Feature:

**Collections Transfer / Handling Desk — Every Object Gets a Route. No Route Resolves the Object.**

Ancestor:

The twelve fixed Catalogue 0 accessions, the three-zone Collections Environment / Exception Board, and the conserved corridor in which one freight-lift Button 0 remains the only descent into the collection.

Room density classification:

**CROWDED.** ELSEWHERE already contains a full access sequence, corridor diagram, environmental exception board, twelve disclosed accession records, Lost & Found material and exit architecture. The useful evolutionary gap was operational depth between those surfaces, not another object or another full-width scene.

Generation mode:

**DEEPEN.**

Selection pressure:

The collections store had become convincing as a place and rich as a fictional catalogue, but its objects mostly sat still. Preventive-conservation zones could describe storage conflicts and the deterministic misfile control could reveal records, yet there was little sense of the ordinary collections work that connects accession, storage and handling. Growth needed to make existing material interact as museum infrastructure without turning the room into a management game.

Retained trait:

Mundane institutional procedure colliding with impossible provenance. Catalogue 0 remains confident about what staff should do to the material while refusing to convert the contradiction into evidence, explanation or real-world claim.

Growth introduced:

A compact **Collections Transfer / Handling Desk** now lives inside the existing catalogue hierarchy. Opening any of the twelve native disclosure records updates one movement docket with:

- the current accession and title;
- exactly one established storage route — Zone A Paper / Film, Zone B Building Fabric, or Zone C Optical / Unassigned;
- an ordinary material-handling instruction that can proceed without resolving provenance;
- a contradiction hold stating what museum procedure must not silently normalise.

The existing deterministic **OPEN NEXT MISFILE** action uses the same record-opening path, so it also moves the transfer docket. Manual disclosure remains authoritative and progressive; no new selector or parallel catalogue is introduced.

What was merged / reframed / pruned:

No visitor-facing artifact was removed. The environment board was tightened so all twelve accessions are accounted for by the same three routes used by the transfer desk, especially the previously under-described paper/manual/warranty records. Growth therefore comes from a relationship among existing surfaces rather than a thirteenth accession or another top-level section.

Net visitor-facing surface change:

**Slightly up.** One compact operational desk is added inside Catalogue 0; the number of top-level regions and accession records is unchanged.

Pattern intentionally avoided:

Not another artifact, impossible label, random misfile, freight-lift scene, creepy archive file, score, queue, resource-management mechanic, visitor choice system or PAGE FOUR-style evidence puzzle. The transfer desk has no success state and no way to optimise the collection.

Future evolutionary headroom created:

Catalogue 0 now has a stable operational relationship that later generations can deepen without enlarging the shelf: movements can acquire richer conservation consequences, accessions can disagree with routing rules, storage zones can develop procedural dependencies, or other ordinary museum workflows can intersect the same twelve records. Future growth should prefer new relationships or institutional systems over raw artifact count.

Resulting fitness:

- makes ELSEWHERE behave more like a working collections store while preserving its reality problem;
- connects all twelve existing accessions to the established environmental model instead of inventing another collection layer;
- keeps the contradiction explicitly fictional and refuses procedural handling as proof of provenance;
- adds no visitor free text, persistence, analytics, tracking, geolocation, polling, timer loop, remote runtime asset, third-party dependency or new network request;
- preserves native `<details>` disclosure, keyboard behavior, responsive layout, increased-contrast handling, print behavior and reduced-motion-safe scrolling;
- remains static, dependency-free, same-origin and compatible with the existing offline shell.
